# pikos-core

Product logic with no I/O, no UI and no Tauri: schedule transitions, calendar
layout, quick-add parsing, text extraction, deep links. The desktop app and the iOS app
(through `pikos-ffi`) share it, so a rule lives here once.

## What belongs here

- **Logic ports, locale and pixels don't.** Anything whose output a person reads in their own
  language (collation, date labels) stays in the platform layer, even when the code looks
  pure. Calendar layout returns column assignment, not geometry, because font metrics and row
  heights belong to one renderer.
- **Dates are local wall-clock strings**, as stored. See `src/dates.rs`.

## How it's tested

The TypeScript implementation in `packages/core` is the reference, and each ported module is
graded against a corpus generated from it (`tests/corpus/`, run by the `*_parity.rs` tests).
Where the input space is combinatorial (the parser, recurrence, calendar layout), a `*_fuzz.rs`
test grades random compositions too. Corpora are regenerated by their generator scripts, never
edited by hand.

A passing corpus says the port handles what someone thought to write down. A fuzzer is only as
good as the axes its generator varies, so confirm one with a mutation of the Rust side before
trusting a clean run.
